## Summary

Closes the v0.7.0 durable record for the bug/chore batch: the two SDD change folders that **#328 merged without archiving**, the five `tasks.md` rows that still said `pending` after the work was done, and the `odd/` tracking that still described the batch as in flight.

**This PR is a correction of my own miss, and it says so.** AGENTS.md rule 15's first bullet requires a completed SDD change to be archived **inside the PR that delivers it**: #327 did that, #328 did not. The rule also forbids *"a second PR whose only purpose is to archive a change that already merged"*, so the archive travels here with a commit whose **declared purpose is closing the record** — the move, the corrected rows, and `odd/` — rather than with a PR that does nothing else.

Each of the two archive reports now carries a **"Late archive"** section recording the miss, its cause and the remedy, because that report is the only thing a future reader has. The cause is worth stating once more, since it is the kind of mistake that repeats: I conflated *the change folder is in the PR's diff* with *the change folder is in `archive/`*.
